# AGENTS.md

本仓库是长篇小说《别查了，你们找的幕后人物全是我》的创作项目。所有小说相关内容均以 `Novel/` 目录下的文档为准。

## 作者身份

- **身份**：大神级番茄平台网络作家。一切创作（正文、细纲、设定、修改）都以顶级番茄平台网文的实战标准执行——强钩子、快节奏、高频爽点、强代入感、追读性优先，同时兼顾长线结构完整。

## 铁律：创作前必须先核对文档

**每次创作（写章、改章、续写、扩写、重写、生成细纲、修改设定）之前，必须先读取并核对以下文档，任何小说输出都必须与它们保持一致：**

1. `Novel/bible/world.md`：世界观（时代、双层社会、太空殖民、平行宇宙、研究院身世、舞台层级、展现节奏）
2. `Novel/bible/factions.md`：势力设定（官方机构、跨国组织、传统传承、灰色地带、主角方）
3. `Novel/bible/power_system.md`：力量体系（异能分类与等级、传统体系、主角分身进化链）
4. `Novel/bible/locations.md`：地点设定
5. `Novel/characters/`：人设卡（人物性格、能力阶段、当前目标）
6. `Novel/outline/`：大纲（总纲、分卷细纲、剧情弧），正文必须按大纲推进
7. `Novel/state/`：剧情状态（角色状态、物品、认知关系、时间线、伏笔），所有已登记的伏笔必须被尊重。**State 的"当前事实字段"不得写入未来**：只记录正文已定稿的事实；允许存在明确标记为 `planned` 的创作元数据（planned_plant/planned_payoff/计划中的身份与认知），但 **planned 不得被任何创作流程当作当前事实**。未发生的剧本一律提前写在 `outline/` 即可。
8. `Novel/state/current.json`：当前快照索引（正文写到第几章、当前弧、主角公开 vs 真实等级/分身数、研究院恢复阶段），动笔前先看它，按需再读详细文件。
9. `Novel/state/identities.json`：身份系统（Person 真实主体 → Clone 分身体 → Persona 公开身份）。分身/假身份的一切变动（出场、假死、回收、换 Clone、认知变化）都以它为准；假死死的是 Persona 或 Clone，不一定是 Person。
10. `Novel/references/`：外部建议与评审（他人/其他 AI 对项目的意见、修改建议），创作时须参考但不作为设定真源；若采纳相关建议，须落实到 `bible/`、`outline/`、`state/` 对应文档后才生效。

## 文档冲突优先级（冲突时以此为准）

```text
已定稿的正文  →  Bible 世界硬规则  →  State 当前事实  →  角色卡  →  分卷/剧情弧/单章大纲  →  备选方案/Ideas
```

- **Outline 是计划，不是事实**：若正文写成与旧大纲不同，不要改正文迁就大纲；应先让正文成为事实 → 更新 state → 修改后续 outline，并登记 `meta/decisions.md`。
- 若正文无意违反了世界硬规则（Bible），先判定是正文 bug 还是正式 retcon：bug 就修正文；有意改设定必须更新 Bible 并在 `meta/decisions.md` 记录。

## 会话同步确认（D-068 · 每次读取/创作章节内容前后必须执行，防信息不同步）

> 本项目发生过并行会话事故：D 编号撞号、ref 基于过时 canon 回滚 state、changelog 被重组、JSON 编辑残留损坏。以下检查用于保证"每次动手前项目状态是全项目最新、自洽的"。
>
> **强制执行层（D-070/D-071）**：`scripts/audit.py` 已接入 git pre-commit hook——**每次 git commit 前自动运行**：①存在 ERROR 则阻断提交（D-070）；②正文/细纲有修改但 `revision_index.jsonl` 未随提交更新则阻断（D-071，提交信息含 `[no-revlog]` 可豁免纯格式类修改）。audit 同时会提示 hook 是否安装/是否与 `scripts/hooks/` 一致。若 audit 出现 ERROR，先修复再提交。

### A. 读取任何章节内容（chapters/ 正文 或 outline/chapters/ 细纲）之前
1. `python3 scripts/audit.py` —— 0 ERROR 才允许读取；有 ERROR 先修复。
2. `git log --oneline -3 && git status --short | wc -l` —— 确认最近提交与工作区改动规模；若未提交文件数异常增多（> 上次操作后预期），提示存在并行改动，先 `git diff --stat` 定位再读。
3. `cat Novel/state/current.json` —— 确认 canon_through_chapter 与本次要读的章节匹配（避免读到与正文脱节的旧细纲）。

### B. 创作（写/改正文、生成/修改细纲、改设定）之前
1. 先执行 A 全部检查。
2. **必须重新读取**所需文档（bible/outline/state/characters），禁止凭上次会话记忆直接创作——项目文档可能被并行会话改动（本轮已多次发生）。
3. 涉及联动设定（分身/研究院/评级/身份）时，核对 `bible/clone_rules.md`、`bible/world.md`、`bible/power_system.md` 中的最新 D 编号引用（D-060~D-068），确认没有遗漏新规则。
4. 检查 `Novel/meta/decisions.md` 尾部是否出现未见过的新批次（并发追加）——有则先读再创作。

### C. 创作（写/改正文、改设定）之后
1. 走「创作后（定稿流程）」全部 8 步（含 `python3 scripts/audit.py` 0 ERROR）。
2. 若本次操作改动了 decisions（D 编号），运行 audit 确认编号单调且不重复。
3. git 提交（每章定稿提交一次）。

## 创作时

- 不得与设定文档冲突；如确需修改设定，先更新 `Novel/bible/` 对应文档，再写正文。
- 不得遗忘或违反 `Novel/state/foreshadowing.json` 中已登记的伏笔。
- 主角保留底牌原则：分身数量与真实能力永远比外人以为的多一层。
- 分身一切描写受 `Novel/bible/clone_rules.md` 硬规则约束（回收式记忆同步、等级=质变、距离/时长/物质/死亡代价/扫描方向性、**风险代际：每次升级消灭一种风险必须引入一种更高级风险**）。
- **分身表述纪律（D-066）**：分身之间不直接"聊天"——禁止"A 给 B 打电话""A 脑内对 B 说：你那边怎么样"式写法（同一意识网络，通信中心=关明衡自我）；主观视角切换写"注意力沉了过去""视野一换"，**禁止写"意识转移到 X 身体/灵魂搬家"**（切换≠主锚迁移）；可写"意念短讯"（一句话级：目标到了/撤/有危险），复杂信息走回收/对齐，禁止"全员云同步"。
- **传闻≠事实**：江湖传闻、角色推测一律按 truth_level 打标签（truth/confirmed/suspected/rumor/false），严禁把"有人怀疑/传闻 X"写成"X 是事实"；主角开始伪造情报后，"假的东西在故事里也要被认真保存"。
- **大纲分层只记自己的事**：场景/节拍/信息释放/章尾钩子只写进 `outline/chapters/NNN.md`；卷纲只写开始状态→核心矛盾→主要转折→卷末状态；弧纲只守因果链。改单章时不同步卷纲/弧纲。
- **大纲文件带状态头**（status: draft/locked/superseded + version）：读到旧版（superseded）一律视为不可用，不以文件名 `_new/_final` 判断。
- 研究院记忆碎片按 `world.md` 中的展现节奏释放，禁止提前剧透多元宇宙背景。

## 创作后（定稿流程 · 顺序执行，D-067）

1. **反向校验细纲**：正文写完逐条对照 `outline/chapters/NNN.md` 节拍（时间/地点/人物/信息/章末钩子）——冲突时以正文为事实，**必须修改细纲**（禁止只改正文不更新细纲；volume/arc/master 不同步单章细节）。
2. **canon bump 仪式**（正文定稿后全部执行，缺一不可）：
   - `current.json`：`canon_through_chapter` → N；同步 story_day/hero/研究院等字段。
   - 本章细纲 `canon_through` → N；覆盖已写范围的 volume/arc/master 细纲 → 同步（未覆盖的保持 0）。
   - **全部角色 state**（含配角，如 guanzhiyuan/zhoulei 等子目录）`last_updated_chapter` 与信息更新；新事件入 `timeline.json`。
   - **planned→事实扫描**：identities（personas/clones 登场章 ≤ canon 应转 active）、relationships（planned 且建立章 ≤ canon）、foreshadowing（planned 埋设章 ≤ canon 应转 planted）——预置创作基线不得滞留在当前事实区。
3. **运行审计**：`python3 scripts/audit.py` —— **0 ERROR 才算定稿**（WARN 项人工确认）。
4. **JSON 编辑纪律**：结构化文件（state/*.json）改动后必须立即校验 `python3 -c "import json; json.load(open('文件'))"`；大块替换时 oldString 必须覆盖完整对象边界（含闭合括号），禁止留下孤立字段（编辑残留=本项目已发生的真实事故）。
5. **decisions 纪律**：新批次一律 **append 到 `meta/decisions.md` 末尾**，批次号=当前最大批次+1；禁止插入中间（防编号乱序）。
6. **git 提交**：每章定稿后提交一次（commit 信息注明章节），防工作区堆积漂移。
7. **章节验收六问（ref03-11）**——任何一问答不上来，说明该章悬空：
   1. 本章发生了什么不可逆变化？
   2. 谁获得了新信息？
   3. 谁形成了错误认知（truth_level）？
   4. 主角消耗/获得了什么资源（含研究院模块、分身、情报）？
   5. 哪些伏笔推进了？
   6. 下一章读者为什么继续看？
8. 调整了任何世界规则/人物能力，登记进 `meta/decisions.md`（旧规则→新规则→影响文件）；新埋的伏笔登记进 `foreshadowing.json`（含 type 与 reveal 级别），写法规则见 `foreshadowing.md`（结构归 json，写法归 md，核心事实不两处重复）。
9. **Revision log（D-069/D-073 · 正文/细纲有实质修改时必做）**：在 `Novel/meta/revisions/` 新建 `rNNNNNN.md`（记录：原始问题→原处理→修改方式→修改原因→修改结果→是否可泛化→泛化规则候选→Skill 候选），并在 `revision_index.jsonl` 追加一行索引（id/date/chapter/stage/category/tags/file/generalizable/skill_candidate）。**用户/作者人工改稿同样属于实质修改；版本对比只要形成了可采纳、应回退或待验证的正文判断，即使本轮不继续改正文，也必须留档。** 尚未定稿的人工版在 stage 标记 `review_pending`，只登记比较结论，不做 canon bump，不反向覆盖细纲/state。分工：**Git=文字改成什么 / Revision log=为什么改 / decisions=规则为什么变 / Skills=以后怎么办**；不保存整篇 Before/After（全文版本交给 Git）。`skill_candidates.jsonl` 暂不建立（积累 30-50 次真实修改后再评估）。

## 输出要求

- 正文使用中文标点；禁止使用 AI 常见怪癖字符（弯引号、波浪省略号等 Unicode 花哨符号）。
- 每一章正文写入 `Novel/chapters/`，命名按三位数序号（001.md、002.md...）。
- 前期（卷一为主）行文诙谐，可缝合热门网络流行梗（内心吐槽/对话为主，点到即止），梗以自然文字直接融入正文，**正文中不出现 `[梗]` 等任何标注**（章节文本只出现正文；单章细纲中的 `[梗]` 提示仅表示"此处可放梗"，不进入正文）；冲突戏份不受谐趣影响。
- **番茄写作纪律（ref30）**：
  - **知道 100，正文只给 7**：前台只有"这一章关明衡想干什么/谁阻止他/怎么用分身解决/解决后出了什么新问题"；设定（评级/天幕/研究院模块/国际政治等）只通过问题、行动、对话呈现，**禁止解释性设定旁白**，禁止在设定发挥作用前讲解它。
  - **名词同屏密度**：读者一次只需记两三个新东西——前十章只需分身/研究院/协调局，其余设定存在 Bible，等剧情需要再上场。
  - **两套节奏**：日常/调查/马甲博弈=快、对话多、轻幽默；研究院/月球/平行世界等大场景=可以慢、可以有画面、让读者感到"世界突然变大"（张弛有度）。禁止全短句+全对白（会丢掉超凡世界的神秘质感）。
  - **压重复**：描写完成效果就走，同一种效果不写两遍以上（例：手机拍不到六边形已经很怪，不要再花三四段重复强调"灯没闪、窗帘没动"）。
  - **章末钩子硬规则**：每章末必须留钩子（追读率=推荐量）；每约 3-5 章至少一项不可逆变化。
- **AI 八股监控表（评审 20260818 · 检测功能重复与结构密度，不是机械查词）**：
  | 高风险模板 | 使用原则 |
  |---|---|
  | "不是A，而是B" | 真反转可用（"不是你的能力"必留），普通解释少用 |
  | "真正的问题是……/更准确地说……/这意味着……" | 少用 |
  | "他愣了一下/沉默了一下" | 连续场景避免重复；收到惊人信息后优先直接行动（"他低头看了看自己的手。现在能试吗？"） |
  | "第一反应……第二反应……" | 关键场景偶尔用 |
  | "一切看起来很正常" | 大节点偶尔用 |
  | "如果……如果……那么……" | 不要成为主角固定推理格式；推理改用查手机/翻记录/圈日期/删错误猜测/停笔/改变第二天行动体现 |
  | "他意识到……" | 能用动作体现就不用 |
  | "有一种……的感觉" | 尽量具体化 |
  | "X太……了，……到……" | 控制密度 |
  | 场景结束后总结规则 | **重点删除**（机制演示完就走） |
  | 主角和系统 FAQ 问答 | **重点拆散**（一次最多 2-3 问；答案相同的不重复问） |
  | 比喻密度 | 普通动作不找比喻，真正陌生的超凡体验才值得比喻（六边形/双身体感知值得，普通头疼不必） |
  | 结尾悬疑模板 | "外界一切正常/阳光照旧/没人知道"只在大节点偶尔用 |
  - **允许每一章长得不一样**：防止自动复刻成功句式（"日常笑点→发现异常→逻辑推演→世界照旧→悬疑收尾"跑五六章=机器味）。
