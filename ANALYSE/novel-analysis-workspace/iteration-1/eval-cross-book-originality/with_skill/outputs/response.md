# 身份反转规则库提炼约定

当前未提供三本书的分析产物，因此我不会虚构跨书规律。请为每本书提供 `book_id`，以及已完成的 `distilled/`、剧情弧报告、专题分析和统计结果路径；默认不读取整本原文，仅在现有报告无法支撑判断时使用必要的短证据引用。

## 工作流

1. **输入验收**：确认三本书均已完成单书蒸馏，身份相关剧情弧和专题报告可追溯；不合格的书先补齐，不以印象代替证据。
2. **单书抽象**：逐书提取身份反转候选机制，统一拆成“认知基线、隐藏信息、信息差、铺垫、触发、见证顺序、验证链、收益、代价、失效条件”，不保留具体剧情复述。
3. **跨书归并**：比较共有循环、题材变体、中后期膨胀或失效条件。至少两本书独立支持的机制才进入跨书规则库；仅见于一本的做法标为“单书假设”，不得包装成通用规律。
4. **原创化改写**：保留因果机制，删除专名、独有世界观术语、连续事件序列、标志性桥段、可识别原句和作者句式模板。每条可用规则必须要求新书同时改变情境、核心资源和人物关系，并给出可变参数，而非替换名词式改写。
5. **审计交付**：逐条检查来源覆盖、适用边界、失效风险和反向可识别性；若仅凭规则描述即可猜出某一本书，则继续抽象或剔除。

## 输出契约

交付一份 `identity-reversal-rulebook.md`，包含三部分：

### 1. 跨书对照表

按候选机制列出支持书目数量、各书变体、共同机制、关键差异、适用阶段和失效条件。只记录 `book_id` 与分析报告路径，不收录原句。

### 2. 身份反转规则卡

每条规则固定包含：

- `rule_id`：稳定编号。
- `规则公式`：一句去情节化的因果表达。
- `支持度`：`3/3`、`2/3` 或“单书假设”。
- `来源锚点`：对应的 Book DNA、剧情弧或专题报告路径。
- `前置条件`：成立所需的信息差、关系和资源条件。
- `执行节拍`：铺垫、误判累积、触发、验证、余波的功能顺序；不复刻任何原作事件链。
- `预期收益`：身份反转承担的剧情功能，如关系重估、权限重排或目标升级。
- `代价与风险`：巧合感、降智、重复揭露、战力或系统膨胀等风险。
- `失效条件`：何时不应使用，以及中后期为何会钝化。
- `原创变量`：新书必须重新设计的情境、资源、人物关系、见证者和验证方式。
- `置信度`：高、中、低，并说明降级原因。

### 3. 原创性审计

逐条给出“通过／退回”，并检查：无专名、无原句、无标志性桥段、无连续事件复刻、无作者句式模仿；所有正式规则均获至少两书支持；所有规则均包含适用边界、失败条件和三项原创变量。

在收到上述输入前，交付状态只能标记为“待蒸馏”，不能生成规则结论。
